***O que e um Microcontrolador***

um microcontrolador ! microprossessador

Um microcontrolador ja inclui:

    - CPU
    = Memoria de programa (Flash)
    - Memoria de dados (SRAM)
    - EEPROM
    - Perifericos (timers, UART, ADC, GPIO, etc)

    Tudo no mesmo chip


**ATmega 128 - Arquitetura**
    CPU
        - Arquitetura RISC
        - 8 bit
        - Single ALU
        - Sem FPU (nada de floating point nativo)
        - ate ~16 MIPS @ 16 MHz
        - 32 registos gerais (32 x 8 bits)

        Muito importante:
            - Execucao em linha unica
            - Sem paralelismo
            - Sem multiplos nucleos

***Arquitetura Harvard***
    Memoria de programa e memoria de dados sao separadas.

    Isso permite:

        - Buscar instrucao
        - Aceder a dados

    quase em paralelo
    E diferente da arquitetura VON NEUMAN

**MEMORIA**
    Flash 12 KiB
    SRAM 4 Kib
    EEPROM 4 KiB

Nota critica:
4 KB de RAM e extremamente limitado.
Qualquer uso  descuidado de stack -> crash

**Perifericos:**
    53 GPIO
    4 Timers
    2 USART
    ADC 10-bit
    SPI
    Wachdog
    Comparador Analogico

Aqui comeca a parte interessante para sistemas embebidos reais.

⚠️ 1️⃣ Sem FPU → Floating Point é em Software

No ATmega128:

Não existe unidade de vírgula flutuante (FPU)

Tudo que seja float ou double é feito por rotinas em software

Muitas instruções → muitos ciclos → muito lento

Exemplo mental:

int a = 10;
int b = 3;
int c = a / b;   // simples

float x = 10.0 / 3.0;  // biblioteca inteira chamada

Em AVR:

int → 1–2 ciclos

float → dezenas ou centenas de ciclos

📌 Em sistemas embebidos:

Usa-se fixed-point

Ou escala inteira (ex: temperatura ×100)

Isto é pensamento de firmware a sério.

**2 Memory Map - Parte Critica**
o sliude mais importante foi este:

 **Data Memory (64 KiB address space)**
 Enderecamento de 16 bits:
    2^16 = 65536 bytes = 64 Kib

Mas atencao 
Isto e o espaco total possivel, nao quer dizer que esteja tudo preenchido.

📍 Organização Real da Data Memory
Endereço	Conteúdo
0x0000–0x001F	32 registos (R0–R31)
0x0020–0x005F	64 I/O registers
0x0060–0x00FF	Extended I/O
0x0100–0x10FF	4 KB Internal SRAM
>0x1100	External SRAM (se existir)

🔥 Isto é brutal:

Os registos estão mapeados na memória.

Ou seja:

R0 = endereço 0x0000

O AVR trata registos como memória especial.


**Registo R26-R31 (X,Y,Z)

Sao usados para:

isto e arquitetura classica RISC bem elegante

**6. Stack e Impacto de Performance**
importante
Se colocares a stack em memoria externa:
    - cada push/pop demora mais
    - INterrupcoes ficam mais lentas
    Isto e critico em sistemas tempo-real.

#### Num microcontrolados simples como AVR:
    1. nao ha branch prediction.
    2. noa ha pipeline avancado
    3. o CPU executa uma instrucao de cada vez.

    o microcontrolados nao consegue executar a instrucao seguinte antes de saber qual e a proxima.

    Ou seja:
        . Se existe um if ou branch, CPU tem de esperar.

Loop unrolling

O compilador pode transformar isto:

for (i=0;i<4;i++)
    sum += a[i];

em:

sum += a[0];
sum += a[1];
sum += a[2];
sum += a[3];

Agora:

não há comparação

não há salto

menos ciclos

Trade-off:

vantagem	desvantagem
mais rápido	código maior
menos branches	mais Flash usado

Em microcontroladores isso é muito comum.
