## 1. Objetivo da aula

A aula parece ter tido dois objetivos encadeados. Primeiro, preparar o ambiente de desenvolvimento para Raspberry Pi 4 com compilação cruzada do kernel e dos módulos, para que os alunos consigam compilar localmente e depois testar no Pi. Segundo, introduzir programação de baixo nível no Raspberry Pi por acesso direto a registos, tanto em user space via `/dev/mem` como em kernel space via módulo de kernel, com foco em PWM, controlo de GPIO e um exercício de “blink LED”.
A intenção pedagógica não foi só “fazer funcionar”, mas mostrar a transição entre três níveis: datasheet/registos → mapeamento em C → integração no Linux. Isso está alinhado com a lógica de cross-compilation para Pi 4 e com a distinção entre user space e kernel module para aceder ao hardware.

## 4. Arquitetura provável do código

### Módulos/ficheiros prováveis

* **`pwm_user.c` ou similar**
  Programa user space que abre `/dev/mem`, faz `mmap()` dos registos físicos do GPIO/PWM/clock e manipula duty cycle.
* **`blinker.c`**
  Módulo de kernel com:

  * `blinker_init`
  * `blinker_exit`
  * `blinker_open`
  * `blinker_release`
  * `blinker_read`
  * `blinker_write`
  * callback de timer
* **`Makefile`**
  Build out-of-tree do módulo `.ko`.
* **`overlay.dts` / `*.dtso`**
  Overlay para declarar o dispositivo usado no exercício final.
* **Script ou comandos de deploy**
  `insmod`, `rmmod`, `mknod`/udev, leitura/escrita em `/dev/blinker`.

### Responsabilidades

* **Camada de mapeamento de registos**

  * definir structs/offsets dos registos
  * converter GPIO number em índice/bit
* **Camada de controlo GPIO**

  * `setGpioFunctionOutput(gpio)`
  * `setGpioValue(gpio, 0|1)`
* **Camada PWM**

  * configurar modo PWM “traditional”
  * ativar canal 0
  * escrever duty cycle em `DATA`
* **Camada de módulo de kernel**

  * mapear memória física com API do kernel
  * configurar timer
  * exportar interface `/dev/blinker`

### Fluxo de execução provável

1. `insmod blinker.ko`
2. `blinker_init()`:

   * mapeia registos
   * configura GPIO12 como output ou função alternativa PWM
   * inicializa timer
   * regista major/minor e operações `file_operations`
3. processo de user space abre `/dev/blinker`
4. `blinker_open()` marca módulo em uso
5. `write("/dev/blinker", "500\n")` altera período
6. timer callback alterna estado do LED/GPIO
7. `read("/dev/blinker")` devolve período atual
8. `close()` chama `release`
9. `rmmod` descarrega módulo

### Dados/estados importantes

* `ledStatus` ou equivalente
* `period_ms`
* ponteiro para base dos registos mapeados
* indicador de módulo em uso
* `struct timer_list blink_timer`

### Interação entre componentes

* user space fala com `/dev/blinker`
* `/dev/blinker` encaminha para `file_operations`
* módulo usa API do kernel para timer + mapeamento de I/O
* o exercício final substitui parte da configuração fixa por device tree/overlay

## 5. Reconstrução técnica da aula

### Ponto de partida

Os alunos precisavam primeiro de conseguir **compilar para Raspberry Pi 4**, mesmo sem terem o Pi físico naquele momento. O professor empurrou a turma para cross-compilation local, precisamente para evitar bloqueios logísticos e garantir que os `.ko`, `Image` e `dtb` podem ser produzidos antecipadamente. Isso é coerente com a prática recomendada em embedded Linux: toolchain externo, `bcm2711_defconfig`, build do kernel e dos módulos, e só depois deploy para o alvo.

### Problema

Depois da preparação do ambiente, o problema técnico da aula parece dividir-se em dois:

1. **Como controlar GPIO/PWM no Raspberry Pi por acesso direto a registos**
2. **Como encapsular isso num módulo de kernel controlável por um ficheiro de dispositivo**

### Decisão

O professor não quis começar por frameworks de alto nível. Em vez disso:

* mostrou o mapeamento dos registos
* falou nos bits de controlo
* insistiu em GPIO12 / PWM0
* mandou usar o “traditional PWM approach”
* depois reutilizou a mesma lógica em kernel module

Isto sugere uma intenção pedagógica clara: o aluno deve ser capaz de ler a datasheet, identificar registos, e traduzir isso em C.

### Implementação

Provável ordem real usada pelo professor:

1. Instalação ou preparação dos headers e do source do kernel
2. Cross-compilation para Pi 4
3. Introdução ao PWM hardware:

   * registo de controlo
   * bits que ativam canal
   * registo `DATA` define duty cycle
4. Introdução ao acesso user-space:

   * `/dev/mem`
   * `mmap()`
   * estrutura C para os registos
5. Evolução para kernel module:

   * `module_init/module_exit`
   * `file_operations`
   * timer do kernel (`timer_setup`, `mod_timer`)
   * `try_module_get/module_put`
   * criação de `/dev/blinker`
6. Exercício de adaptação:

   * pegar no código base
   * piscar LED por GPIO
   * permitir alterar período
7. Fecho com exercício mais avançado:

   * medir frequência de PWM com interrupções
   * criar overlay/device tree

### Validação

Os sinais de validação implícitos na aula são:

* compilar sem erros
* gerar `.ko`
* conseguir carregar com `insmod`
* criar/usar `/dev/blinker`

### 6.1 Estrutura mínima do módulo `blinker.c`

```c
// [INFERIDO] includes típicos observados/compatíveis com a explicação
#include <linux/module.h>
#include <linux/kernel.h>
#include <linux/fs.h>
#include <linux/uaccess.h>
#include <linux/timer.h>
#include <linux/io.h>

// [INFERIDO] estado global
static struct timer_list blink_timer;
static int led_status = 0;
static unsigned int period_ms = 500;
static volatile void __iomem *gpio_base;
static int device_opened = 0;

// [HIPÓTESE] major dinâmico
static int blinker_major;

// [INFERIDO] funções auxiliares vindas do quadro/slides
static void set_gpio_output(unsigned gpio);
static void set_gpio_value(unsigned gpio, int value);

// [INFERIDO] callback do timer
static void blink_timer_cb(struct timer_list *t)
{
    led_status = !led_status;
    set_gpio_value(12, led_status);   // [OBSERVADO] GPIO12 foi o GPIO referido
    mod_timer(&blink_timer, jiffies + msecs_to_jiffies(period_ms));
}

// [OBSERVADO] professor referiu init/exit + configuração inicial
static int __init blinker_init(void)
{
    // [INFERIDO] mapear registos GPIO com ioremap
    gpio_base = ioremap(/* GPIO_BASE_PHYS */, /* size */);
    if (!gpio_base)
        return -ENOMEM;

    set_gpio_output(12);
    set_gpio_value(12, 0);

    timer_setup(&blink_timer, blink_timer_cb, 0);
    mod_timer(&blink_timer, jiffies + msecs_to_jiffies(period_ms));

    blinker_major = register_chrdev(0, "blinker", &blinker_fops);
    if (blinker_major < 0) {
        del_timer_sync(&blink_timer);
        iounmap(gpio_base);
        return blinker_major;
    }

    return 0;
}

static void __exit blinker_exit(void)
{
    unregister_chrdev(blinker_major, "blinker");
    del_timer_sync(&blink_timer);
    set_gpio_value(12, 0);
    iounmap(gpio_base);
}
```

### 6.3 `read` / `write`

```c
// [INFERIDO] o ficheiro dispositivo serve para ler/escrever o período
static ssize_t blinker_read(struct file *file, char __user *buf,
                            size_t len, loff_t *off)
{
    char tmp[32];
    int n;

    if (*off > 0)
        return 0;

    n = scnprintf(tmp, sizeof(tmp), "%u\n", period_ms);
    if (copy_to_user(buf, tmp, n))
        return -EFAULT;

    *off = n;
    return n;
}

static ssize_t blinker_write(struct file *file, const char __user *buf,
                             size_t len, loff_t *off)
{
    char tmp[32];
    unsigned long val;

    if (len >= sizeof(tmp))
        return -EINVAL;
    if (copy_from_user(tmp, buf, len))
        return -EFAULT;

    tmp[len] = '\0';

    if (kstrtoul(tmp, 10, &val))
        return -EINVAL;

    if (val == 0)
        return -EINVAL;

    period_ms = (unsigned int)val;
    return len;
}
```

### 6.5 Funções GPIO auxiliares

```c
// [HIPÓTESE] reconstrução típica BCM2711; precisa validação com datasheet/slides
static void set_gpio_output(unsigned gpio)
{
    unsigned reg = gpio / 10;
    unsigned shift = (gpio % 10) * 3;
    u32 v = readl(gpio_base + GPFSEL_OFFSET + reg * 4);
    v &= ~(0x7 << shift);
    v |=  (0x1 << shift);   // output
    writel(v, gpio_base + GPFSEL_OFFSET + reg * 4);
}

static void set_gpio_value(unsigned gpio, int value)
{
    unsigned reg = gpio / 32;
    unsigned bit = gpio % 32;

    if (value)
        writel(1 << bit, gpio_base + GPSET_OFFSET + reg * 4);
    else
        writel(1 << bit, gpio_base + GPCLR_OFFSET + reg * 4);
}
```

## 1. Objetivo da aula

A aula/folha prática junta dois blocos técnicos complementares. O primeiro é **acesso HW/SW em user space** no Raspberry Pi 4, usando `/dev/mem` + `mmap()` para controlar GPIO e o periférico PWM diretamente por registos físicos. O segundo é **módulos de kernel carregáveis (LKM)**, onde um template de character device com timer é adaptado para controlar o GPIO 12 do Pi 4 e depois evolui para um “dimmer” por software PWM (“bit banging”).
O objetivo pedagógico é claro: sair da abstração alta, entender **endereços físicos, registos, timers do kernel, file_operations e deploy para o Pi 4**, para depois conseguires implementar o trabalho 2 de forma autónoma.

## 2. Evidência extraída

* A região base de periféricos varia por modelo; no **BCM2711 / Raspberry Pi 4** é `0xFE000000`. 
* Em Linux, user space não acede diretamente a endereços físicos; a ficha manda usar **`/dev/mem` + `open()` + `mmap()`**, e executar com `sudo`.
* A toolchain pedida é **GNU Aarch64 para host x86-64**, com binário `aarch64-none-linux-gnu-gcc`; a ficha sugere um symlink `~/bin/arm-gcc`.
* Exercício 1 da PL4: programar um **blink LED** por acesso direto a registos GPIO. 
* Os registos de configuração GPIO estão a partir de `base + 0x200000`. Cada GPIO usa **3 bits** em `GPFSEL[]`; valor `001` significa **output**.
* Para escrever valor lógico usa-se **GPSET** para pôr a 1 e **GPCLR** para pôr a 0; não se escreve diretamente “0/1” no mesmo registo.
* A própria ficha fornece a estrutura `bcm2837_gpio_registers_t` com `GPFSEL`, `GPSET`, `GPCLR`, `GPLEV`, etc. 
* A ficha manda usar um LED em série com cerca de **1 kΩ** e lembra que GPIO do Pi não deve fornecer continuamente mais de ~3 mA.
* Exercício 2 da PL4: usar o **PWM0 canal 0** no **GPIO12**, com registos do primeiro módulo PWM em `base + 0x20C000`.
* A frequência base de referência para PWM no Pi 4 é **54 MHz**; mantendo o relógio por omissão, o programa deve usar `CHN0_RANGE = 255`, pôr `CONTROL.PWEN1 = 1`, e escrever o valor desejado em `CHN0_DATA`. 
* O PDF `LinuxKernelModule-en.pdf` fornece um template de módulo `blinker.c` com:

  * `PISCA_MAJOR 500`
  * `struct timer_list my_timer`
  * `led_status`
  * `blink_delay = 3*HZ`
  * `pisca_open`, `pisca_release`, `pisca_read`, `pisca_write`
  * `my_timer_func`
  * `init_module`, `cleanup_module`.
* O template é um **character device driver**, registado por `register_chrdev_region`, `cdev_init`, `cdev_add`, e exposto em `/dev/blinker`.
* `pisca_read()` devolve o período em milissegundos; `pisca_write()` recebe texto com período em ms e converte-o para `blink_delay` em jiffies. 
* O módulo usa `try_module_get()` e `module_put()` para proteger contra remoção durante uso. 
* O enunciado do LKM manda criar `/dev/blinker` com `mknod /dev/blinker c major_number 0`, carregar com `insmod`, testar com `cat /dev/blinker`, `echo ... > /dev/blinker`, e observar `dmesg`.
* O módulo expõe parâmetros via `sysfs`: `/sys/module/blinker/parameters/blink_delay` e `/sys/module/blinker/parameters/led_status`. 
* Exercise II do LKM manda adaptar para **Raspberry Pi 4**, criar `blinker-rpi4.ko` a partir de `blinker.o + gpio.o`, e guardar `ARCH=arm64 CROSS_COMPILE=...` no Makefile.
* Exercise III do LKM manda implementar `dimmer-rpi4.ko`, PWM por **software bit-banging** no GPIO12, com duty cycle 0..10 e período fixo de 10 jiffies. O próprio enunciado dá o pseudofluxo do callback do timer.
* O ficheiro `serialopen.c` que enviaste implementa abertura/configuração de porta série por `termios`, mas **não aparece ligado a estes exercícios de GPIO/PWM/LKM**.

## 5. Reconstrução técnica da aula

### Ponto de partida

O professor quis que os alunos não tratassem o Pi como “Arduino com Linux”, mas sim como um sistema Linux/SoC onde o hardware é acessível por registos e onde o kernel oferece dois caminhos: user-space via `/dev/mem` e kernel-space via drivers/módulos. A base de tudo é saber **onde estão os periféricos** e como mapear registos do BCM2711.

### Problema

Há dois problemas concretos:

1. Como controlar um LED no Pi 4 sem usar bibliotecas high-level.
2. Como encapsular esse controlo numa interface de driver com timer e ficheiro de dispositivo.

### Decisão

A estratégia do professor parece ser:

* primeiro demonstrar GPIO como **saída digital** com `GPFSEL`, `GPSET`, `GPCLR`;
* depois demonstrar PWM hardware no GPIO12 com `CONTROL`, `CHN0_RANGE`, `CHN0_DATA`;
* e só depois passar para módulo de kernel, onde o aluno reutiliza a mesma compreensão de registos dentro de `gpio.c`.

### Implementação

**Parte A — user space / PL4**

* `open("/dev/mem")`
* `mmap()` da janela de registos GPIO
* configurar GPIO18 como output
* escrever no bit correspondente de GPSET/GPCLR em loop para blink
* segundo programa: mapear também PWM0, configurar GPIO12 para alt function PWM, e controlar duty cycle 0..255

**Parte B — kernel module**

* analisar `blinker.c`
* perceber `register_chrdev_region`, `cdev_init`, `cdev_add`, `file_operations`, `timer_setup`, `add_timer`, `del_timer`
* adaptar Makefile para Pi 4 e multi-file build
* implementar `gpio.c` para o BCM2711
* substituir os comentários `//..` por escrita física real
* testar no Pi com `/dev/blinker`
* evoluir para `dimmer-rpi4.ko` com duty cycle 0..10 em jiffies

### Validação

O professor quer validação por:

* geração de executáveis/`.ko`

### 6.2 `gpio.c` provável para o trabalho 2

```c
// [INFERIDO] reconstrução fiel ao enunciado PL4 + LKM, ainda precisa validar offsets no Pi real
#include <linux/io.h>
#include <linux/types.h>
#include "gpio.h"

#define BCM2711_PERIPH_BASE   0xFE000000UL   // [OBSERVADO] PL4
#define BCM2711_GPIO_OFFSET   0x00200000UL   // [OBSERVADO] PL4
#define BCM2711_GPIO_BASE     (BCM2711_PERIPH_BASE + BCM2711_GPIO_OFFSET)

typedef struct {
    uint32_t GPFSEL[7];
    uint32_t GPSET[3];
    uint32_t GPCLR[3];
    uint32_t GPLEV[3];
    uint32_t GPEDS[3];
    uint32_t GPREN[3];
    uint32_t GPFEN[3];
    uint32_t GPHEN[3];
    uint32_t GPLEN[3];
    uint32_t GPAREN[3];
    uint32_t GPAFEN[3];
    uint32_t GPPUD;
    uint32_t GPPUDCLK[3];
} bcm2837_gpio_registers_t; // [OBSERVADO] nome no PDF

static volatile bcm2837_gpio_registers_t __iomem *gpio_regs;

int gpio_init_output_12(void)
{
    u32 v;
    gpio_regs = ioremap(BCM2711_GPIO_BASE, sizeof(bcm2837_gpio_registers_t));
    if (!gpio_regs)
        return -1;

    // GPIO12 -> GPFSEL1 bits 6..8 = 001
    v = ioread32(&gpio_regs->GPFSEL[1]);
    v &= ~(0x7 << 6);
    v |=  (0x1 << 6);
    iowrite32(v, &gpio_regs->GPFSEL[1]);

    // default off
    iowrite32(1u << 12, &gpio_regs->GPCLR[0]);
    return 0;
}

void gpio_set_12(int value)
{
    if (value)
        iowrite32(1u << 12, &gpio_regs->GPSET[0]);
    else
        iowrite32(1u << 12, &gpio_regs->GPCLR[0]);
}

void gpio_cleanup_12(void)
{
    if (gpio_regs) {
        iowrite32(1u << 12, &gpio_regs->GPCLR[0]);
        iounmap((void __iomem *)gpio_regs);
        gpio_regs = NULL;
    }
}
```

### 6.3 `blinker.c` adaptado

```c
// [OBSERVADO + INFERIDO]
#include <linux/module.h>
#include <linux/fs.h>
#include <linux/cdev.h>
#include <linux/uaccess.h>
#include <linux/timer.h>
#include "gpio.h"

#define PISCA_MAJOR 500          // [OBSERVADO]
#define RWBUFSIZE 11             // [OBSERVADO]

MODULE_LICENSE("GPL");

static struct timer_list my_timer;       // [OBSERVADO]
static unsigned char led_status = 0xFF;  // [OBSERVADO]
static dev_t devno;                      // [OBSERVADO]
static struct cdev pisca_cdev;           // [OBSERVADO]
static unsigned int blink_delay = 3*HZ;  // [OBSERVADO]
static int device_open = 0;              // [OBSERVADO]

module_param(led_status, byte, S_IRUSR|S_IWUSR);      // [OBSERVADO]
MODULE_PARM_DESC(led_status, "Port status");          // [OBSERVADO]
module_param(blink_delay, uint, S_IRUSR|S_IWUSR);     // [OBSERVADO]
MODULE_PARM_DESC(blink_delay, "Half period in jiffies"); // [OBSERVADO]

static int pisca_open(struct inode *inode, struct file *filp)
{
    if (device_open)
        return -EBUSY;
    device_open++;
    try_module_get(THIS_MODULE);   // [OBSERVADO]
    return 0;
}

static int pisca_release(struct inode *inode, struct file *filp)
{
    device_open--;
    module_put(THIS_MODULE);       // [OBSERVADO]
    return 0;
}

static ssize_t pisca_read(struct file *filp, char __user *buf,
                          size_t count, loff_t *f_pos)
{
    static char local_buf[RWBUFSIZE];
    static int len;
    static unsigned int period_ms;
    int len1;
    int res;

    if ((*f_pos) == 0) {
        period_ms = blink_delay * 1000 / HZ * 2;   // [OBSERVADO]
        sprintf(local_buf, "%d\n", period_ms);     // [OBSERVADO]
        len = strnlen(local_buf, RWBUFSIZE - 1);   // [OBSERVADO]
    }

    len1 = len - (*f_pos);
    len1 = len1 > count ? count : len1;

    res = copy_to_user(buf, local_buf + (*f_pos), len1); // [OBSERVADO]
    if (res != 0)
        printk(KERN_WARNING "Bytes left to copy\n");

    (*f_pos) += len1;
    return len1;
}

static ssize_t pisca_write(struct file *filp, const char __user *buf,
                           size_t count, loff_t *f_pos)
{
    static char local_buf[RWBUFSIZE];
    int period_msec;
    int res, i;
    char c;

    for (i = 0; i < count; ++i, ++(*f_pos)) {
        if ((*f_pos) > RWBUFSIZE - 2)
            return -1;

        res = copy_from_user(&c, buf + i, 1);      // [OBSERVADO]
        if (res != 0)
            printk(KERN_WARNING "Bytes left to copy\n");

        if (c == '\n') {
            local_buf[*f_pos] = 0;
            period_msec = simple_strtol(local_buf, NULL, 0); // [OBSERVADO]
            blink_delay = period_msec * HZ / 2000;           // [OBSERVADO]
            printk(KERN_WARNING "New period: %d ms\n", period_msec);
            return i + 1;
        } else {
            local_buf[*f_pos] = c;
        }
    }
    return count;
}

static struct file_operations pisca_fops = {   // [OBSERVADO]
    .owner   = THIS_MODULE,
    .read    = pisca_read,
    .write   = pisca_write,
    .open    = pisca_open,
    .release = pisca_release,
};

static void my_timer_func(struct timer_list *unused)
{
    led_status = ~led_status;               // [OBSERVADO]
    gpio_set_12((led_status != 0) ? 1 : 0); // [INFERIDO] substitui comentário //..
    my_timer.expires += blink_delay;       // [OBSERVADO]
    add_timer(&my_timer);                  // [OBSERVADO]
}

int init_module(void)
{
    int result;

    devno = MKDEV(PISCA_MAJOR, 0);         // [OBSERVADO]
    result = register_chrdev_region(devno, 1, "blinker"); // [OBSERVADO]
    if (result < 0)
        return result;

    cdev_init(&pisca_cdev, &pisca_fops);   // [OBSERVADO]
    pisca_cdev.owner = THIS_MODULE;        // [OBSERVADO]
    pisca_cdev.ops = &pisca_fops;          // [OBSERVADO]
    result = cdev_add(&pisca_cdev, devno, 1); // [OBSERVADO]
    if (result)
        printk(KERN_NOTICE "Error %d", result);

    if (gpio_init_output_12() != 0)        // [INFERIDO]
        return -ENOMEM;

    timer_setup(&my_timer, my_timer_func, 0); // [OBSERVADO]
    my_timer.expires = jiffies + blink_delay; // [OBSERVADO]
    add_timer(&my_timer);                    // [OBSERVADO]
    return 0;
}

void cleanup_module(void)
{
    del_timer(&my_timer);                 // [OBSERVADO]
    gpio_cleanup_12();                    // [INFERIDO]
    cdev_del(&pisca_cdev);                // [OBSERVADO]
    unregister_chrdev_region(devno, 1);   // [OBSERVADO]
}
```

### Módulo

### Device file

* `mknod /dev/blinker c 500 0` se o major for mesmo 500
* `cat /dev/blinker` devolve algo como `6000` ms por defeito

  * porque `blink_delay = 3*HZ` e `period_ms = blink_delay*1000/HZ*2` 
* `echo 1000 > /dev/blinker` altera o período
* `cat /dev/blinker` devolve o novo período

### Hardware

* LED em série com ~1 kΩ entre GPIO e GND
* no Pi real, nunca 5V no GPIO
* GPIO12 como alvo do LKM adaptado
* GPIO18 como alvo do blink user-space da PL4

### PWM hardware (PL4)

* `CHN0_RANGE = 255`
* `CONTROL bit 0 = 1`
* `CHN0_DATA` varia 0..255
* brilho do LED muda no GPIO12

### Erros prováveis

* `command not found` por copiar output do `ls`
* `No such file or directory` por paths do toolchain
* `Permission denied` sem `sudo` ao usar `/dev/mem`
* `Segmentation fault` se o `mmap()` estiver mal alinhado
* `invalid module format` se o módulo não casar com o kernel do Pi
* LED não pisca:

  * GPIO12 não configurado
  * resistor/ligação errada
  * `gpio_set_12()` a escrever no registo errado
